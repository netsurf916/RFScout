# CC1101

CC1101 is RFScout's receive-only sub-GHz activity application. Shared SPI/service/lifecycle rules are defined in [Platform architecture](../ARCHITECTURE.md); planned history/timing improvements belong in [ROADMAP.md](../ROADMAP.md).

## Availability and lifecycle

The application performs a startup hardware probe and is available only when the selected runtime profile legally provides a working CC1101 service. The current T-Embed profile advertises that provider.

Activation starts the session-managed scanner worker. The worker must quiesce before the application session can be reclaimed.

## Scanning

The scanner performs receive-only RSSI sweeps. Current scan profiles are:

- 433 MHz;
- 315 MHz;
- 868 MHz;
- 915 MHz; and
- Manual.

The application allows adjustment of the scan range and supported frequency step. The service keeps at most 128 samples in a completed sweep.

## Presentation and classification

The UI renders live spectrum/activity information and conservative signal-shape categories derived from recent sweeps.

Current categories are:

- Narrow ISM;
- Remote-sensor-like;
- Continuous carrier;
- Bursty signal; and
- Wideband activity.

These labels describe observed RF behavior. They are not decoded protocol/product identity.

### Classification policy

The current classifier operates on contiguous active regions in completed RSSI sweeps. Activity is considered present when the normalized sweep level is at least **54**. A segment spanning at most four bin intervals is treated as narrow. The classifier also compares the current sweep with its short classifier history: a drop of at least **28** normalized level units from the recent maximum is treated as evidence of burst-like behavior.

For each active segment, the current decision order is:

1. a narrow segment in a common ISM region with recent stronger history becomes **Remote/sensor**;
2. otherwise, a narrow segment with current level at least **110** becomes **Continuous** only when the recent-history maximum is no more than **12** normalized level units above the current maximum;
3. otherwise, a narrow segment with recent stronger history becomes **Bursty RF**;
4. any remaining narrow segment becomes **Narrowband**; and
5. a wider segment becomes **Wide RF**.

The reported classifier confidence values are fixed heuristic strengths associated with those branches (62, 58, 52, 48, and 40 respectively), not calibrated probabilities. The classifier has a short warm-up/confirmation history and its fixed arrays are working state for this heuristic, not retained RF captures.

The application keeps a small fixed classifier summary and supports accumulated detection counts, notifications, and count reset.

## Observation history and timing

Completed confirmed activity episodes are retained in growable app-session PSRAM. Each history record keeps the classified behavior, center frequency, bandwidth, peak RSSI, first/last observed time, observed duration, and the gap since the previous completed observation of the same category near the same frequency. History growth is geometric and the entire collection is reclaimed with the CC1101 app session.

These timings are derived from completed RSSI sweeps. They describe when RFScout observed activity across successive scans; they are not decoded packet, symbol, pulse-width, or protocol timing measurements. If PSRAM growth fails, live scanning/classification continues and the new completed history record is dropped while a drop counter is retained for diagnostics.

### SD telemetry example

When SD logging is available, the active app emits one-second summary telemetry. This captured hardware record is representative:

```json
{"type":"telemetry","time":"2026-09-23T22:38:42Z","app":"CC1101","low_khz":432800,"high_khz":433200,"step_khz":5,"likely":5,"detected":true}
```

`likely` is the number of fixed classifier-summary rows copied by the current telemetry path. It is currently **5** because CC1101 exposes five category rows; it is not a count of active detections. `detected` reports whether the CC1101 service is presently detected/usable. The record is operational telemetry, not a decoded-protocol claim.

## Current limitations

The current activity model does not yet expose the growable observation history through a rich on-device drill-down, and it does not perform protocol-level pulse/symbol decoding. The existing fixed sweep/classifier arrays remain algorithmic working state rather than retained RF captures.
